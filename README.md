# Hasenstadt

Приложение для изучения немецкого вдвоём. Набор статических файлов плюс одна
бесплатная база. Ни сборки, ни терминала, ни платных сервисов.

Понадобится примерно час, спокойно и без спешки. Нигде не просят карту.
Если где-то попросили карту — значит, свернул не туда: вернись на шаг назад.

---

## Блок А. Аккаунт GitHub

Это место, где будут лежать файлы и откуда приложение будет открываться.

1. Открой **github.com**.
2. Нажми **«Sign up»** (зарегистрироваться), справа сверху.
3. Введи почту. Лучше ту, которой пользуешься.
4. Придумай пароль и имя пользователя (**«username»**) — латиницей, без пробелов.
   Оно попадёт в адрес сайта, пусть будет коротким: например, `matt-hasen`.
5. Подтверди почту: GitHub пришлёт код, его надо вписать.
6. Если спросят про тарифы — выбирай **«Free»** (бесплатно).

Запиши на бумагу: имя пользователя и пароль GitHub.

## Блок Б. Папка с файлами

1. Нажми **«+»** справа сверху → **«New repository»** (новая папка).
2. В поле **«Repository name»** впиши `hasenstadt`.
3. Оставь переключатель на **«Public»** (открытый). Это важно: бесплатный сайт
   работает только у открытых папок. Ничего секретного внутри нет.
4. Нажми **«Create repository»** (создать).
5. На открывшейся странице найди ссылку **«uploading an existing file»**
   (загрузить готовые файлы). Если её не видно — **«Add file»** → **«Upload files»**.
6. Перетащи мышкой в окно браузера **всё содержимое** папки с программой:
   `index.html`, `config.js`, `manifest.json`, папки `css`, `js`, `data`, `img`
   и остальное. Именно содержимое, а не папку целиком.
7. Внизу нажми **«Commit changes»** (сохранить изменения).

## Блок В. Включить сайт

1. В своей папке нажми **«Settings»** (настройки) — вкладка сверху справа.
2. В левом столбце найди **«Pages»** (страницы).
3. В разделе **«Source»** (откуда брать) выбери **«Deploy from a branch»**.
4. Ниже в **«Branch»** выбери `main`, папку оставь `/ (root)`, нажми **«Save»**.
5. Подожди пару минут и обнови страницу. Сверху появится адрес вида
   `https://matt-hasen.github.io/hasenstadt/`

Запиши на бумагу: этот адрес.

Пока не заполнен `config.js`, по адресу будет открываться страница с надписью
про невписанный адрес базы. Так и должно быть, это не поломка.

## Блок Г. База данных

1. Открой **supabase.com**, нажми **«Start your project»**.
2. Выбери вход через GitHub (**«Continue with GitHub»**), разреши доступ
   (**«Authorize»**).
3. Нажми **«New project»** (новый проект) и заполни:
   - **«Name»** — `hasenstadt`;
   - **«Database password»** — нажми **«Generate a password»** и сразу скопируй
     пароль на бумагу. В файлы программы его вписывать не надо никогда;
   - **«Region»** — `Central EU (Frankfurt)`, это ближайший к вам обоим.
4. Тариф — **«Free»**. Нажми **«Create new project»** и подожди несколько минут.

Запиши на бумагу: пароль базы.

## Блок Д. Таблицы

1. В левом столбце панели Supabase найди **«SQL Editor»** (редактор запросов).
2. Нажми **«New query»** (новый запрос).
3. Открой файл `db.sql` из папки с программой, скопируй его целиком и вставь
   в большое поле.
4. Нажми **«Run»** (выполнить) — кнопка справа снизу, или `Ctrl+Enter`.
5. Внизу должно появиться сообщение об успехе. Если появилось красное сообщение —
   не паникуй: скопируй его и покажи Клоду, это чинится за минуту.
6. Проверить: в левом столбце **«Table Editor»** должны появиться `app_user`,
   `settings`, `word_progress` и остальные.

Скрипт можно запускать повторно сколько угодно раз: ничего не ломается
и не затирается.

## Блок Е. Два входа

1. В левом столбце найди **«Authentication»** (вход) → **«Users»** (пользователи).
2. **«Add user»** → **«Create new user»** (создать вручную).
3. Впиши свою почту и придуманный пароль. Обязательно включи
   **«Auto Confirm User»** (сразу подтвердить) — иначе вход будет ждать письма.
4. Повтори то же самое для Амико, с её почтой и паролем.
5. Закрой дверь за собой: в разделе **«Authentication»** найди настройки входа
   по почте (**«Providers» → «Email»**, либо **«Sign In / Providers»**) и выключи
   переключатель, разрешающий регистрацию новым людям
   (**«Allow new users to sign up»** или **«Enable sign ups»**).

Запиши на бумагу: обе почты и оба пароля.

## Блок Ж. Связать программу с базой

1. В панели Supabase открой **«Project Settings»** → раздел **«API»**
   (или **«API Keys»**).
2. Скопируй два значения:
   - **«Project URL»** — похож на `https://abcdefgh.supabase.co`;
   - **«anon public»** — очень длинная строка. Это публичный ключ, его можно
     класть в файлы, он на то и сделан.
     Ключ с пометкой **«service_role»** не трогай никогда и никуда не вставляй.
3. Вернись на GitHub, открой файл `config.js`, нажми значок карандаша
   (**«Edit this file»**), вставь адрес и ключ вместо слов-заглушек.
4. Там же впиши обе почты в поле `NAMES`, чтобы имена в интерфейсе встали верно.
5. Нажми **«Commit changes»** и подожди минуту: сайт обновляется не мгновенно.

## Блок З. Первый вход

1. Открой адрес приложения.
2. Войди своей почтой и паролем.
3. Поставь галочку у правила, пройди несколько карточек.
4. **Главная проверка:** закрой браузер, почисти в нём кэш, зайди снова.
   Прогресс должен быть на месте.
5. Зайди с другого браузера — прогресс тот же.
6. Пусть Амико зайдёт своей почтой со своего ноутбука.

## Блок И. Телефон

1. Открой на телефоне тот же адрес и войди.
2. В меню браузера выбери «Добавить на главный экран».

## Блок К. Чтобы база не засыпала

Проект на бесплатном тарифе засыпает, если к базе неделю никто не обращался.
Файл `.github/workflows/keepalive.yml` уже лежит в папке — осталось вписать в него
свои значения:

1. На GitHub открой `.github/workflows/keepalive.yml`, нажми карандаш.
2. Замени `АДРЕС_ПРОЕКТА` и `ОТКРЫТЫЙ_КЛЮЧ` на те же, что в `config.js`.
3. **«Commit changes»**.
4. Проверь: вкладка **«Actions»** сверху → слева выбери `keepalive` →
   **«Run workflow»** (запустить) — убедись, что проходит без ошибки.

Запрос идёт каждый понедельник. Ответ будет пустым, и это нормально:
важен сам факт обращения к базе.

## Блок Л. Что записать на бумагу

Один листок, положить туда, где не потеряется:

- адрес приложения;
- имя пользователя и пароль GitHub;
- почта и пароль Мэтта для входа в приложение;
- почта и пароль Амико;
- пароль базы Supabase;
- строка «панель базы: supabase.com, вход через GitHub».

Этот листок — единственное, что нельзя потерять. Всё остальное восстанавливается.

## Если что-то сломалось

| Что видно | Что делать |
|---|---|
| Пустой экран или «адрес базы не вписан» | Не дописан `config.js`. Блок Ж. |
| Страница не открывается совсем | Проверь адрес по бумажке. Подожди пару минут после заливки файлов. |
| «Почта или пароль не подошли» | Проверь раскладку и Caps Lock. Пароль меняется: supabase.com → проект → «Authentication» → «Users» → три точки у нужного человека. |
| Плашка «не сохранено, повторяю» | Ничего не делай, работай дальше: всё отправится само. |
| «База уснула» | supabase.com → проект → кнопка восстановления («Restore project» или «Resume»). Пара минут — и всё работает. Прогресс цел. |
| Изменения в файлах не видны | Поменяй `CONTENT_VERSION` в `config.js`, обнови страницу через `Ctrl+F5`. |
| Голос молчит | Настройки → «проверить голос». Если молчит и там: Windows → Параметры → Время и язык → Речь. |
| Упражнений на слух нет | Значит, немецкий голос не найден. Это не поломка, остальное работает. |
| Блок слов не загрузился | Файл с ошибкой. `Ctrl+Shift+I` → вкладка «Console» → показать Клоду. |
| Всё сломалось целиком | Настройки → «Загрузить копию» и выбрать последний скачанный файл. |
| GitHub Pages упорно не работает | План Б: `app.netlify.com/drop` — перетащить туда ту же папку. База при этом та же. |

**Правило на случай паники:** прогресс лежит в базе, а не в браузере и не в файлах.
Что бы ни случилось с сайтом, файлами, ноутбуком или браузером — прогресс цел,
пока цела база.

## Как добавлять слова потом

Код при этом не трогается вообще. Меняются только файлы в папке `data`.

1. Получить файл от Клода, например новый `data/words/essen.json`.
2. Зайти в свою папку на GitHub, в `data/words`.
3. **«Add file»** → **«Upload files»**, перетащить файл, **«Commit changes»**.
4. Если это новый блок — открыть `data/topics.json`, нажать карандаш и дописать
   строку про него.
5. Открыть `config.js`, поменять `CONTENT_VERSION` на следующую букву.
6. Подождать минуту, обновить приложение.

**Идентификатор слова (`id`) менять нельзя никогда.** Прогресс хранится по нему.
Исправлять можно всё остальное: перевод, транскрипцию, фразу, даже само немецкое
слово — но не `id`.

Если блок не загрузился, открой консоль разработчика (`Ctrl+Shift+I`, вкладка
«Console») — там прямым текстом написано, в какой строке что не так.

## Проверка связи до установки

Это на две минуты и может сэкономить час. Проверить надо обоим: у вас разные
провайдеры и разные города.

1. Открой **github.com**. Открылся — хорошо. Не открылся — подожди час и попробуй
   снова: доступность GitHub из России последнее время скачет, и это проходит само.
2. Открой **supabase.com**. Обычно открывается штатно.
3. Самое важное — проверить можно только после блока Г, когда проект уже создан:
   открой в браузере адрес своего проекта (тот самый **«Project URL»**, который
   вставляешь в `config.js`). Если увидишь хоть какой-то ответ или страницу —
   канал проходит, всё в порядке. Если страница висит и не открывается совсем —
   значит, твой оператор фильтрует адреса `*.supabase.co`. Чаще это случается
   на мобильном интернете.

Если фильтрует у одного из вас: на том устройстве поможет любой VPN, включённый
только на время занятий. Прогресс при этом не страдает ни в каком случае — он
лежит в базе, а не на устройстве.

Из программы наружу не уходит ничего, кроме запросов в вашу собственную базу.
Библиотека для работы с ней лежит прямо в папке (`js/vendor/supabase.js`),
а не тянется с чужого CDN — это сделано специально, потому что доступ к
зарубежным CDN из России то есть, то нет.

Если GitHub Pages упорно не открывается, в разделе «Если что-то сломалось» есть
план Б: та же папка перетаскивается на `app.netlify.com/drop`, адрес получится
другой, а база остаётся та же и прогресс не теряется.

## Важная мелочь

Приложение всегда открывается **по сетевому адресу**, а не двойным щелчком по
`index.html` с диска. Браузер запрещает модулям работать с диска, и будет пустой
экран. Это не поломка.
